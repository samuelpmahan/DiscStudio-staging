# Source and boundaries

The product surface is a new, dependency-free ES-module staging implementation. It is not a claim that the original Svelte Concept B component tree was patched in place. It carries Concept B's cream/sage, three-column, serif-heading design into the linked product and uses Concept A's footage-context/transparent-overlay interaction. The original production comparison routes remain untouched.

- Reference DiscStudio main: `d5e324c6419e4c1182ec128de72af2ba3f4b0a5f`.
- `src/core/exec.js` is the existing browser-safe ChainSpot board/PQL implementation, taken from DiscStudio `source/candidate-pxc/chainspot/exec.js`, originally attributed to ChainSpot `82f8fc94afd4fa277837e2b4725d7c6e100b1b20`. The only packaging difference is explicit parser injection instead of an implicit npm YAML import; the application supplies JSON.parse to the existing composition reader. It retains the same declaration-ordered runner and actual Part reads/writes.
- `src/core/sha256.js` is the browser-safe synchronous ChainSpot digest implementation from the uploaded research snapshot, with TypeScript annotations removed. Fresh tests compare it with Node's crypto digest. Historical comments are historical context, not a new run report.
- `public/tick-part-checklist.js` is unchanged from neat's `task/review-handoff` checkpoint `07a9ccfd66f4bb5a4180ef597bcf64637fa59e90`. Blob SHA: `5211d64411f3fc72535027eec15c0df40dc70971`.
- `src/review.js` subclasses that real neat custom element. It adds per-item comments, author name, context capture and checkpoint-scoped export, without manufacturing acceptance or promotion.

No upstream code, dependencies, credentials, corpus or private runtime data are bundled beyond the named small runtime components and illustrative local seed. This checkpoint was implemented and inspected directly, not delegated to independent agents.
