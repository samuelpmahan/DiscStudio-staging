# CAPTURE.md: the run-record contract for experiments/runs/dayN/

Every day of the week (research/ULTRACODE-WEEK.md, "Days") is executed as a
multi-agent run: parallel lanes with disjoint targets, adversarial lenses that
try to reject each lane's output, and a synthesizer that merges survivors. The
run itself is evidence. This file says exactly what is retained about it, where,
and in what shape, so that a later reader (or Day 5's generate_returns.py) can
cite a file in the repository rather than a scratch directory or a memory.

The record for day N lives at `pyto/experiments/runs/dayN/`. It is written by
the synthesizer at the end of the day and completed by the orchestrator after
the commit (commit_sha). Nothing under `runs/` is executed by
`scripts/check_all.sh`; it is a record, not a suite.

## Required files

| File | Content | Produced by |
| --- | --- | --- |
| `prompt.md` | The orchestrating brief the day ran from: the verbatim "Day N" section of research/ULTRACODE-WEEK.md plus the verbatim text of every critic gap/amendment that names Day N. If the orchestrator's lane briefs differ from the plan text, the lane briefs are appended under "Lane briefs as issued". | orchestrator, at the start of the day |
| `candidates/` | Scratch or alternative implementations that were considered and not merged: a lane's rejected draft, a competing design, a spike that informed the merged version. One file or subdirectory per candidate, named `<lane>-<short-name>.<ext>`, each with a one-line header stating why it was not merged. Empty (`.gitkeep`) is acceptable when every lane's first draft survived; say so in `meta.json.notes`. | lanes and lenses |
| `verdicts/<lens>.json` | One file per adversarial lens (`mutation.json`, `semantics.json`, `prohibition.json`, `completeness.json`, ...). Shape: `{"lens": str, "day": int, "verified_at_sha": str, "findings": [{"target": "<file>:<line>", "verdict": "accept" \| "reject" \| "missing", "reason": str, "evidence": str}]}`. A `reject` names the test or file that was dropped; a `missing` names a rule that no test covers (the completeness critic lists these rather than dropping them). | each lens |
| `diff.patch` | `git diff <base_sha>..<commit_sha> -- pyto ':(exclude)pyto/experiments/runs'` (the run record excludes itself). Until commit_sha is known: `git diff <base_sha> -- pyto ':(exclude)pyto/experiments/runs'` against the working tree, regenerated by the orchestrator after the commit. | synthesizer, then orchestrator |
| `tests.txt` | The full `-v` output of every suite the day's `scripts/check_all.sh` runs, i.e. `bash scripts/check_all.sh > runs/dayN/tests.txt 2>&1`. check_all.sh prints each suite's complete `unittest -v` log followed by the per-suite count table, so this one file holds every `Ran N tests` line and every test name. | synthesizer |
| `mutation-kill.md` | One row per characterization test: `rule` (one sentence), `file:line` characterized, `mutated line` (the one-line change applied to a scratch copy of src, never the repo), `test that caught it` (the unittest id that failed against the mutation), `status` (`killed` or `survived -> deleted`). A test that survives its mutation is deleted, not kept (research/ULTRACODE-WEEK.md, kill criteria: "Day 1: any characterization test that survives its one-line library mutation is deleted"). | mutation lens |
| `meta.json` | `{"day": int, "base_sha": str, "commit_sha": str \| "pending", "date": "YYYY-MM-DD", "agents": [{"lane": str, "role": str, "targets": [str]}], "tokens": int \| null, "notes": str}`. `commit_sha` is `"pending"` while the synthesizer writes; the orchestrator replaces it after committing and regenerates `diff.patch`. `tokens` is null when the harness did not report usage; never estimated. | synthesizer, then orchestrator |

Optional, when they exist: `lenses.md` (the lens briefs as issued), `timing.md`
(wall time per lane when reported by the harness).

## Rules the record enforces

1. Every number in a verdict or in `mutation-kill.md` cites a file and line
   (`pcr.py:159-160`, `test_semantics.py:88`), and every test named must appear
   in `tests.txt`. A claim without a citation is a `missing` finding, not an
   `accept`.
2. Retained code contains no lambdas and no `<function ...>` reprs; Calculations
   are module-level functions in an explicit `REGISTRY` (plan, Day 1 prohibition
   lens). The prohibition lens greps `diff.patch` and every evidence JSON for
   `lambda` and `<function`.
3. Feature subsets are never enumerated; only leave-one-group-out variants are
   run (plan, Day 1: "confirms no 32,768-subset enumeration").
4. New files use LF line endings. src/pyto/*.py are CRLF and are left as they
   are (`{?} LineEndings`, research/ULTRACODE-WEEK.md open judgments).
5. Library changes are at most one seam per day; on Day 1 `git diff --stat
   <base_sha> -- pyto/src` must be empty and the prohibition lens records that
   it checked.

## sys.path: what is logged and what is forbidden

Two different things look alike in a test file and must not be confused.

- An **intra-repo sys.path insert** is a test or script inside this repository
  putting another directory *of this same repository* on `sys.path` so that a
  reference module can be imported under its own top-level name. Example:
  `experiments/s3-synthetic/test_s3_synthetic.py` inserts
  `pyto/reference/chainspot-quick-anno` because `s3.py` does
  `from investigation import StageInvestigation` (reference/chainspot-quick-anno/s3.py:17)
  and `from pyto import ...` (s3.py:18). This is **allowed and logged**: the
  inserting file states the inserted path and the reason in a comment next to
  the insert, prints one `[<experiment>] sys.path.insert(...)` line to stderr
  at import so it appears in `tests.txt`, and asserts at test time that the
  inserted path is inside the repository. `PYTHONPATH=.` for
  `consumers/discstudio-card/experiments/disc-stats` is the same category
  (intra-directory: it names `stats.py` in the cwd) and is whitelisted by name
  in `scripts/check_all.sh`.
- **Cross-repository injection** is any `sys.path` insert or `PYTHONPATH` that
  reaches outside this repository (another checkout, a worktree, `/mnt/d/...`,
  a scratch directory) to satisfy an import. It is **forbidden** by
  docs/worktree-workflow.md:17 ("Run library and affected consumer checks
  without cross-repository sys.path or PYTHONPATH injection"). It is also
  forbidden for `PYTHONPATH` to contain `src`: the library is reached through
  the editable install on Days 1-4 and through the wheel on Day 5, never by
  pointing at `pyto/src` (critic gap 8).

The isolation lens greps `tests.txt` for `PYTHONPATH` and `sys.path.insert`
and accepts only the whitelisted intra-repo lines above.

## How a day closes

A day is closed when `runs/dayN/` holds all seven required entries,
`tests.txt` ends with check_all.sh's `ALL SUITES PASSED` line, `meta.json`
has a real `commit_sha`, and every lens verdict file exists (a lens with no
rejections still writes a file with an empty `findings` list, so absence means
the lens did not run).
